From two CSV files to one endpoint

Two tables, one question

One table holds each Pokémon’s stats. The other lists past battles by ID number, with the winner. Joined together, every battle row carries both fighters’ HP, Attack, Defense, Sp. Atk, Sp. Def and Speed.

pokemon.csv  → stats per Pokémon
combats.csv  → first, second, winner (IDs)
label        → first_wins (1 or 0)

Teach it to compare

A decision tree can only ask about one column at a time. Adding the gap between the two fighters lets it ask “who is faster?” in a single question. Twelve raw features became eighteen.

diff_Speed = first_Speed - second_Speed
diff_Attack = first_Attack - second_Attack
# ...one gap for each of the six stats

A hundred trees, one vote

A random forest trains many different trees and lets them vote. Settings were chosen with 5-fold cross-validation on the training data, and the model was graded once on a locked test set of 10,000 battles.

RandomForestClassifier(
    n_estimators=100, random_state=42, n_jobs=-1
)

Names in, winner out

The saved model sits behind a FastAPI endpoint. It looks up both Pokémon, builds the same eighteen features used in training, and returns the predicted winner with the model’s probability.

POST /predict
{"first": "Charizard", "second": "Blastoise"}

→ {"winner": "...", "probability_first_wins": 0.0-1.0}

Run it anywhere

The Dockerfile bundles Python, the pinned libraries and the trained model, so the API behaves the same on any machine. Then open the automatic docs page and try a matchup.

docker build -t pokemon-predictor .
docker run -p 8000:8000 pokemon-predictor
# open http://127.0.0.1:8000/docs
